# Seeing Voice: review site

A static, multi-page site for the conceptual review of displays that make voice and sound visible to non-expert viewers.

Open `index.html` in a browser. No server is needed.

## Pages

| Page | What it shows |
|---|---|
| `index.html` | Inclusion criteria and the gallery of display types. The demo section is currently hidden (`hidden` on its `<section>`) |
| `studies.html` | All studies as a timeline wall or a sortable evidence table, with shared filters. Filters are kept in the URL, e.g. `studies.html?display=spectrum&view=table` |
| `method.html` | Criteria in full, training levels, coding scheme, open decisions, existing reviews, excluded studies, verification list |
| `verify.html` | Checks: claims against their sources and study coding against the papers. Saves into `data/claims.csv` and `data/checks.csv` (Chrome/Edge write directly; other browsers download the files) |

## Working files

- `data/checks.csv`, `data/claims.csv`: the checklist and the claims made from each source; edit them on `verify.html`.
- `data/references.csv`: bibliographic details of cited sources; `build.py` writes `data/references.bib` for import into Zotero (File → Import).
- `SEARCH.md`: search plan, decisions needed before searching, areas not yet searched.

## Editing the data

The CSV files are the source of truth.

- `data/studies.csv`: one row per study. Column meanings and allowed values are on the Method page.
- `data/displays.csv`: one row per display type. `rank` orders the gallery (0 = raw signal … 5 = learned mapping; 9 = outside scope). `demo_key` picks the demo image used as its thumbnail.

After any edit, run:

    python3 build.py

This checks the coding (unknown values, missing display ids, duplicate ids, exclusions without a reason) and writes `data/data.js`, which the pages load. Pages read `data.js` rather than the CSVs because browsers block reading local files from a page opened with `file://`.

List columns (`criteria`, `displays`) use `;` between values, e.g. `1;3` or `spec;ripple`.

See `images/README.md`. Files go in `images/<study id>.png`.

## Demo

`demo/` holds the rendered images and audio used on the Overview page, plus `demo/demo.js` (generated manifest).

To regenerate or add recordings, edit `SAMPLES` in `tools/make_demo.py` and run:

    pip install numpy scipy matplotlib soundfile
    python3 tools/make_demo.py

Source recordings are read from `demo/source/`.
